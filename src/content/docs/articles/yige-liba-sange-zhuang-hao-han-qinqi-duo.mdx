亲戚多，关系树会发生什么变化？本文按「关系链 → 称呼」的方式拆开来讲，不谈感情，只讲怎么算、怎么叫。

## 一句话结论

> 每一层多出「兄 / 弟 / 姐 / 妹」并列节点，再向下派生侄、甥、堂表，但单条链的规则不变。

## 关系链怎么拆

这条关系的主链是 **父的兄**，也就是「爸爸的哥哥」。在计算器里打开：[父的兄](/calc/?chain=%E7%88%B6%E7%9A%84%E5%85%84)。

| 关系链 | 换成日常说法 | 通常叫 |
| :--- | :--- | :--- |
| `父的兄` | 爸爸的哥哥 | 伯父 |
| `父的父的兄` | 爸爸的爸爸的哥哥 | 伯公 |
| `父的兄的子` | 爸爸的哥哥的儿子 | 堂哥 / 堂弟 |

上表的称呼由 [relationship.js](https://github.com/mumuy/relationship) v1.2.9 实际计算得出，采用通用叫法；北方、广东等地区叫法可能不同，可在[计算器](/calc/)里切换对照。

## 三个要点

1. 「父的兄」「父的弟」是父辈旁系分支。
2. 「父的兄的子」是堂兄弟，属于下一层。
3. 节点数量增加不改变称谓算法。

## 两个常见误解

- **亲戚多称呼就复杂**：规则不变，只是需要更多排行前缀。
- **分支多亲等就近**：亲等按单条链长计算。
